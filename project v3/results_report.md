# v3 학습·추론 결과와 재검증 보고서

## 요약

단일 HW 헤드 CNN 학습은 2026년 9월 23일 44 epoch에서 조기 종료됐고, 최고 checkpoint는 epoch 36이다. 독립 공격 캠페인의 **102,400개 계수 윈도우 표본**에서 Top-1은 **66.625%**, Top-3는 **96.190%**였다. 대표 계수 `(poly=0, coeff=50)`의 공격 트레이스 10,000개에서는 Top-1 **69.87%**를 기록했다.

대표 계수의 균등 후보 표본 65,254개를 대상으로 100회 공격 실험을 수행했으며, 8개 트레이스부터 표본 내 SR 100%를 관측했다. 전체 `q=8,380,417` 후보 완전 열거와 1024계수 전체 키 복구는 실행하지 않았다. 프로그램의 “전체 키 약 12개 트레이스” 출력은 PI에 기반한 휴리스틱이며, 실측 복구 결과로 인용하지 않는다.

추론 실행 시각은 2026-09-23 10:37:20, 이번 문서·재검증 기준일은 2026-10-14이며 시간대는 Asia/Seoul이다. 이번 작업은 저장된 결과 재검산과 문서 정리이며 추가 학습은 수행하지 않았다.

## 평가 범위와 지표 정의

학습은 `Dataset/1-Dataset`의 profiling set1~3, 총 30,000개 트레이스를 사용했다. set4의 10,000개 트레이스는 checkpoint 선택과 사후 온도 보정에 사용했다. attack 캠페인은 별도 트레이스 10,000개이며, 모델 가중치 학습과 온도 선택에 사용하지 않았다.

- 입력: 연속 96샘플, 시간 피크에서 중심을 +24샘플 이동. 학습 때만 ±1샘플 이동 증강.
- 정답: `u`의 32비트 2의 보수 비트패턴에 대한 Hamming Weight(HW), 클래스 0~32.
- Top-k: 정답 HW가 상위 k개 예측 안에 포함된 윈도우 비율. 단위는 `%`.
- 다수 클래스 기준선: **해당 평가 라벨에서** 가장 빈번한 클래스의 비율. 모든 평가에 8.68%를 고정하지 않는다.
- NLL: 정답 클래스의 평균 음의 로그확률, 자연로그 단위. label smoothing을 사용하는 학습 loss와 정의가 다르다.
- ECE: 확신도 15개 구간에서 예측 확신도와 실제 정확도 차이의 표본 수 가중 평균. 표에는 0~1 비율을 그대로 쓴다.
- GE: 정답 후보의 평균 0-based 순위. 점수가 높은 후보 수에 다른 동점 후보 수의 절반을 더한다.
- SR: 정답이 **유일한 최상위 후보**인 실험 비율. 동점 1위는 성공으로 세지 않는다.
- PI: `H(HW) − NLL / ln(2)`, 단위 bit/trace. 예측확률의 품질 지표이며 전체 키 복구를 보증하는 정보량은 아니다.

무작위 표본 평가의 102,400은 **서로 다른 트레이스 수가 아닌 윈도우 추출 횟수**다. 샘플러는 반복 추출하므로 중복 `(trace, poly, coeff)`가 있을 수 있다. 37개 계수 평가는 각 계수에 동일한 공격 트레이스 2,000개를 적용했다.

## 학습은 epoch 36에서 최고 validation loss를 기록했다

환경은 Apple M5 Pro / 48GB, TensorFlow 2.16.2, Metal GPU, 모델 파라미터 263,297개다. 배치 512개를 만들 때 트레이스 32개에서 각각 계수 16개를 추출했다. epoch당 60,000 step, 30,720,000회 윈도우 추출이며 44 epoch 총 1,351,680,000회 추출이다. 이는 고유 학습 데이터 개수가 아니다.

아래는 `history.csv`의 주요 관측치다. CSV의 epoch 번호는 0-based이고 이 문서에서는 1-based로 바꿨다.

| Epoch | Validation loss | Validation Top-1 |
|---|---:|---:|
| 1 | 1.270607 | 62.164% |
| 5 | 1.193602 | 65.147% |
| 16 | 1.152800 | 66.776% |
| 22 | 1.139847 | 67.286% |
| 29 | 1.131620 | 67.566% |
| **36 (best)** | **1.127164** | **67.926%** |
| 44 (종료) | 1.141117 | 67.102% |

최고 epoch의 validation Top-3는 96.442%다. epoch 37~44에 validation loss가 개선되지 않아 patience 8의 EarlyStopping 조건을 충족했다. 종료 로그 기준 소요 시간은 32.49시간이며, 이 시간은 CSV에서 독립 재계산할 수 없다.

학습률은 epoch 1/5/9/16/22/26/31부터 각각 `1e-3 / 3e-4 / 9e-5 / 2.7e-5 / 8.1e-6 / 2.43e-6 / 1e-6`이었다. 최저 학습률에 도달한 뒤에도 작은 개선은 있었으나, epoch 36 이후에는 best를 갱신하지 못했다.

`config.json`의 `val_steps_per_epoch=20000`은 검증 전체 조합 수를 배치로 나눈 **이론적 값**이다. 실제 `model.fit`은 `args.validation_steps=200`, 즉 epoch마다 102,400개 윈도우만 평가했다. 학습 validation loss는 smoothing 0.05를 포함한다.

## 공격 캠페인의 표본 정확도는 validation보다 1.043%p 낮았다

아래 결과는 `best.keras` 추론으로 얻었다. 전체 계수 표본과 특정 계수 전량은 모집단이 다르므로 따로 해석한다.

| 평가 대상 | 윈도우 수 | Top-1 | Top-3 | Top-5 | 다수 클래스 기준선 |
|---|---:|---:|---:|---:|---:|
| set4 / 전체 계수 무작위 표본 | 102,400 | 67.668% | 96.398% | 97.961% | 8.552% |
| attack / 전체 계수 무작위 표본 | 102,400 | 66.625% | 96.190% | 97.843% | 8.420% |
| set4 / poly0 coeff50 | 10,000 | 70.80% | 97.57% | 98.90% | 8.38% |
| attack / poly0 coeff50 | 10,000 | 69.87% | 97.98% | 99.01% | 8.68% |

공격 표본 Top-1은 해당 다수 클래스 기준선의 약 7.91배다. validation과 attack의 차이는 1.043%p이며, 이번 데이터와 전처리에서 캠페인 전이가 가능하다는 관측을 제공한다. 다른 장비·세션에 대한 일반화나 반복 실행의 통계적 유의성을 증명하지는 않는다.

이번 재검증에서 대표 계수의 저장 확률 `(10000, 33)`로 Top-1/3/5, 기준선, 평균 절대오차를 독립 재계산해 결과 JSON과 일치함을 확인했다. 전체 계수 102,400개 표본의 확률은 저장되지 않았으므로 해당 Top-k는 실행 당시 JSON 기록을 근거로 하며 NPZ에서 다시 계산할 수 없다.

## 온도 보정은 공격 표본의 확률 품질을 개선했다

전체 계수 표본의 온도는 set4에서 `T=0.75`로 선택했다. 대표 계수의 키 랭킹에는 그 계수의 set4 전량에서 별도로 선택한 `T=0.80`을 사용했다. 두 온도는 적용 범위가 다르다.

| 전체 계수 표본 | ECE (비율) | NLL (자연로그) | 평균 확신도 |
|---|---:|---:|---:|
| set4 / 보정 전 | 0.070205 | 0.846262 | 60.811% |
| set4 / T=0.75 | 0.018118 | 0.815268 | 69.442% |
| attack / 보정 전 | 0.064348 | 0.865842 | 60.425% |
| attack / T=0.75 | 0.026798 | 0.838323 | 69.023% |

공격 표본은 원래 정확도 66.625%보다 확신도가 낮았고, 보정 후 ECE와 NLL이 감소했다. 양의 온도 보정은 클래스 순서를 유지하므로 Top-k 개선으로 해석하지 않는다. 보정 후 평균 확신도는 정확도보다 약 2.40%p 높아 잔여 과신이 있다.

set4는 checkpoint 선택에도 사용했으므로 calibration과 모델 선택이 완전히 독립적이지 않다. set4 보정 후 NLL도 온도를 맞춘 동일 표본의 값이다. 다음 실험에서는 선택·calibration·최종 평가를 서로 다른 트레이스로 분리해야 한다.

## 대표 계수는 후보 표본에서 8개 트레이스로 100/100회 성공했다

후보는 seed 42로 `[0,q)`에서 65,536회 균등 추출한 뒤 정답 잔여류를 포함시키고 중복 제거하여 65,254개가 됐다. 정답 파일은 평가 대상과 포함 여부를 지정하는 데 사용하며 다른 후보를 정답 키 값들에서 구성하지 않는다. 각 실험은 공격 트레이스 풀에서 최대 40개를 비복원 추출하며, 실험 간에는 트레이스를 공유할 수 있다.

점수는 `log P_T(HW | window) − log prior(HW)`를 누적한다. 현재 prior는 set4의 **온도 보정 전** 예측 평균으로 추정한다. 이 순서를 포함해 기존 구현을 그대로 재현했으며, 통계적으로 최적의 prior라고 가정하지 않는다.

| 트레이스 수 | GE (후보 표본) | GE × q / 65,254 (추정) | SR (100회) |
|---|---:|---:|---:|
| 1 | 3,144.300 | 403,815.02 | 0% |
| 2 | 342.745 | 44,017.93 | 0% |
| 4 | 5.225 | 671.03 | 26% |
| 6 | 0.085 | 10.92 | 93% |
| 8 | 0 | 0 | 100% |
| 16 | 0 | 0 | 100% |
| 40 | 0 | 0 | 100% |

`q/n_candidates` 배율은 약 128.428이다. 환산 GE는 표본으로부터의 근사이며, 표본 GE가 0이어도 표본 밖 후보가 모두 배제됐다는 뜻은 아니다. 따라서 SR 100%도 전체 q 공간 성공률이 아니다. 100/100 성공은 이번 유한한 실험의 관측치이며 성공확률 1을 입증하지 않는다.

같은 후보 표본에 대한 HW 완벽 오라클은 **40회·최대 12트레이스**의 별도 실험에서 5개 트레이스부터 40/40회 성공했다. 모델 실험과 오라클은 반복 수와 최대 길이가 다르므로 완전히 짝지어진 비교는 아니다. 과거 문서의 “어떤 모델도 6개 미만으로 복구할 수 없다”는 고정 하한 주장은 삭제했다. 엔트로피 기반 평균 추정은 개별 실험의 절대 하한이 아니다.

JSON의 `traces_to_ge0=6`은 코드상 **GE ≤ 0.5에 처음 도달한 시점**이다. 이름과 달리 GE가 정확히 0이 된 시점은 8개다.

## 37개 계수 평가에서는 양끝 계수가 약했다

각 다항식의 `k={0,32,64,96,128,159,191,223,255}`와 `(0,50)`을 평가해 총 37개 계수를 조사했다. 전체 계수의 무작위 표본이 아니라 위치를 고르게 고른 진단 표본이다. 각 계수의 Top-1은 2,000개 동일 공격 트레이스에서 계산하고, PI는 전역 `T=0.75` 보정 후 계산했다.

37개 계수의 평균 Top-1은 63.484%, 계수 간 표준편차는 8.211%p, 최소·최대는 39.35%·70.55%였다. `k=0/255` 경계 계수 8개의 평균은 **50.119%**, 내부 29개는 **67.171%**로, 차이가 **17.052%p**다. 경계 계수를 상대적으로 많이 포함해 전체 계수 무작위 표본의 66.625%와 평균이 다르다.

아래는 PI가 가장 낮은 다섯 계수다. 경계 구간의 취약성을 보여주지만 원인 자체는 아직 검증하지 않았다.

| Poly | Coeff | Top-1 | PI (bit/trace) |
|---|---:|---:|---:|
| 0 | 0 | 39.35% | 1.867 |
| 0 | 255 | 42.85% | 2.049 |
| 1 | 0 | 45.15% | 2.143 |
| 1 | 255 | 49.85% | 2.237 |
| 3 | 255 | 52.65% | 2.450 |

PI 중앙값은 2.984, p5는 2.124, 최소는 1.867bit/trace였다. `log2(q)/PI`의 휴리스틱은 중앙값 약 7.71, p95 약 10.83, 표본 최악 약 12.32트레이스다. 미측정 987개 계수, 후보 전체 열거, 계수 간 의존성, 유한 표본 불확실성을 반영한 복구 보증이 아니다. PI가 양수인 표본만으로 “1024계수 모두 복구 가능”이라고 판정하지 않는다.

## 재검증 결과와 남은 불확실성

2026-10-14 재검산의 18개 점검이 모두 통과했다. 상세 기록은 [audit.json](../artifacts/v3/evaluation_single/audit.json)에 있으며, 원시 결과 JSON의 SHA-256도 기록했다.

1. CSV의 44개 epoch 순서와 epoch 36 best 수치 확인.
2. 대표 계수의 확률 유한성·행 합과 Top-k·온도 재계산.
3. seed 42의 후보 개수와 100회 GE/SR 곡선 재계산, 동점 처리 검사.
4. 저장된 15-bin 집계에서 네 가지 ECE 재계산, 계수 평균·표준편차·PI 중앙값 확인.
5. `best.keras`와 `final.keras`의 **모든 레이어 가중치 배열 49개**가 정확히 동일함 확인. EarlyStopping의 best 복원 동작과 일치한다. optimizer 상태의 동일성을 검사한 것은 아니다.
6. 원래 공격 키로 `u=MR(c*s)`를 전체 10,240,000개 중간값에서 검증: 불일치 0개.

중심 잔여류 `s mod q`로 대표원을 바꾼 MR 출력은 전체 10,240,000개 중 **6,289개(0.061416%)**가 원래 저장 라벨과 다르다. 따라서 모듈러 잔여류의 수학적 동등성을 32비트 HW의 완전 동일성과 혼동하면 안 된다. 현 후보 랭킹은 이 근사를 포함한다.

추가로, 초기 `time_map.json`은 이전 공격 트레이스·라벨 표본을 활용해 만들어진 기록이 있다(기존 README의 600행 탐색). 따라서 attack 캠페인은 **가중치·온도 선택에 미사용**이지만, 전체 설계 과정까지 완전히 미사용인 최종 holdout이라고 부를 수는 없다. 정규화 memmap에는 생성 당시 통계와 입력 해시 manifest가 없어, 전처리의 완전 재현성과 split 경계는 추가 기록이 필요하다. 전처리 함수는 전체 factory 데이터로 통계를 추정하므로 전체 profiling을 넘겼다면 set4 입력도 통계에 포함된다.

평가 판정은 **제한을 명시하면 공유 가능**이다. 기존 모델의 분류 성능과 대표 계수 후보 표본의 랭킹 수치는 재현됐고, 전체 키 복구 및 새로운 캠페인 일반화는 남은 검증 과제다.
