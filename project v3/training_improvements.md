# v3 다음 학습을 위한 개선 분석

## 가장 먼저 개선할 것은 경계 계수와 평가 설계다

현재 CNN은 공격 캠페인 표본 Top-1 66.625%, Top-3 96.190%를 기록했다. 후속 학습의 목표는 평균 정확도를 올리는 것과 함께, 전체 키의 약한 계수에서 안정적인 후보 축소를 얻는 것이다. **경계 계수 취약성의 원인 확인 → 평가 분할 정비 → 윈도우·샘플링 실험 → 멀티태스크·앙상블** 순서를 권한다.

이 글은 2026-09-23 실측 결과와 2026-10-14 재검산에 기반한 실험 제안이다. 개선 실험이나 추가 학습을 실행한 결과는 아니다. 근거는 [결과 보고서](results_report.md), [추론 JSON](../artifacts/v3/evaluation_single/results.json), [재검산 JSON](../artifacts/v3/evaluation_single/audit.json), [학습 CSV](../artifacts/v3/training_single/history.csv)와 아래에 연결한 구현이다.

2026-10-14 문헌 조사로 보완한 [선행 연구 비교와 연구 개선안](related_work_analysis.md)에는 동일 데이터의 CPA·템플릿·MLP 기준선, 위치 조건부 모델, 부분 NTT 복구와 대수적 후처리의 비교 설계를 정리했다. 공개 DTDS와 현재 데이터는 누설 지점·파일 구성이 다르며, 로컬 원출처는 아직 확인되지 않았다. 서로 다른 논문의 트레이스 수와 우리 후보 표본의 SR로 성능 우열을 판단하지 않는다.

## 1. 경계 계수는 평균 성능에 가려진 병목이다

37개 위치 표본에서 `k=0/255` 8개의 평균 Top-1은 50.119%, 내부 29개는 67.171%로 **17.052%p 차이**가 났다. 가장 약한 `(poly0,k0)`은 39.35%, `(poly0,k255)`는 42.85%였다. 위치 표본 평가의 편차가 8.211%p라는 점은 계수 불변 모델이 모든 위치에서 똑같이 동작하지 않는다는 증거다.

현재 [샘플러](v3_stage2_data.py)는 모든 위치에 동일한 96샘플·offset 24를 적용한다. 피크 기준 구간은 `[-24,+72)`이며, 계수 간격 약 30~35샘플보다 길어 이웃 계수 연산도 포함한다. 첫·마지막 계수는 이웃 연산과 전후 문맥이 내부 계수와 다를 수 있다. 시간 매핑 오차, 구간별 누설 세기, 정규화 차이도 가능한 원인이다. **이번 결과만으로 매핑 오차 또는 신호 감쇠로 확정할 수 없다.**

다음 진단은 공격 라벨을 이용해 설정을 다시 맞추기보다 profiling 학습·검증 구간에서 수행한다.

1. 1024계수 각각의 Top-1, unsmoothed NLL, 보정 후 PI를 고정 검증 트레이스에서 측정한다. 계수별 p5·최솟값과 poly별·k 구간별 분포를 저장한다.
2. 경계 위치와 내부 대조군에서 피크 주변 상관/SNR, 윈도우 내 피크 상대 위치, 이웃 연산 문맥을 비교한다. 매핑 재측정은 학습 profiling 데이터만으로 한다.
3. 대표 경계·내부 계수에 대해 중심 offset `16/24/32`를 먼저 진단한다. 성능이 offset에 민감하면 학습 데이터에서 매핑이나 위치별 offset을 수정한다.
4. 원인이 문맥 차이일 경우 짧은 중심 브랜치와 긴 문맥 브랜치를 결합하거나, 경계 전용 작은 헤드를 공유 트렁크에 붙인다. 효과는 경계 계수와 내부 계수에서 동시에 확인한다.

하나의 긴 윈도우를 더 늘리는 것이 항상 유리하지는 않다. 이웃의 무관한 연산이 늘어날 수 있으므로 약한 위치의 PI·후보 랭킹 개선을 기준으로 판단한다.

## 2. 검증·calibration·최종 테스트를 트레이스 단위로 분리한다

현재 set4는 checkpoint 선택과 온도 보정을 겸한다. epoch별 validation은 무한 랜덤 샘플러의 200배치만 평가하고, epoch마다 표본이 바뀐다. 따라서 작은 validation loss 차이에는 표본 변동이 포함될 수 있다. 예를 들어 epoch 27과 29의 best 차이는 약 **0.000031**로 매우 작다.

다음 학습은 set1~3을 학습용으로 유지하고 set4를 트레이스 ID 단위로 selection/calibration/audit 구간으로 나누는 설계가 가능하다. 예를 들어 5,000/2,500/2,500개로 분리하되, 측정 순서의 드리프트가 있으면 연속 구간과 고정 난수 분할의 차이를 분석한다. 동일 트레이스의 다른 계수 윈도우를 서로 다른 split에 넣지 않는다. 정밀한 일반화 비교가 필요하면 4개 profiling set을 번갈아 제외하는 cross-set 검증을 수행한다.

selection에 사용할 `(trace,poly,coeff)` 목록을 저장해 모든 checkpoint와 모델이 같은 입력을 평가하도록 한다. 공간이 충분하므로 각 split의 **1024계수 전량**도 블록 단위로 평가할 수 있다. 사용자 환경에 맞춰 데이터를 임의로 줄이기보다는 I/O와 GPU 추론을 배치화하고 전체 평가를 수행하는 편이 낫다.

초기 시간 매핑과 일부 전처리 설계는 과거 attack 라벨 표본을 보고 정했다. 현재 attack 결과는 개발 평가로 보존하고, 다음 모델의 최종 일반화 주장은 설계에 사용하지 않은 새 측정 캠페인에서 확인해야 한다. 기존 attack 데이터 내부의 새 분할만으로 과거 설계 사용 이력을 지울 수는 없다.

정규화 통계는 split마다 정의를 저장한다. 엄격한 holdout 목적이면 학습 세트 통계만 적용하고, 라벨 없이 대상 캠페인 전체 입력으로 통계를 맞추는 transductive 정규화를 허용한다면 그 프로토콜을 모든 실험에 동일하게 적용한다. 현재 [memmap 생성 함수](v3_stage2_data.py)는 전달된 factory 전체로 mean/std를 추정하며, stats·config manifest를 자동 보존하지 않는다.

## 3. 확률 보정의 이득을 유지하고 prior 계산을 비교한다

전역 온도 `T=0.75` 적용 후 공격 표본 ECE는 **0.064348 → 0.026798**, NLL은 **0.865842 → 0.838323**으로 개선됐다. 원래 확신도는 정확도보다 낮았고, 보정 후에는 평균 확신도가 정확도보다 약 2.40%p 높다. 단순 온도 보정으로 줄일 수 있는 오차와 남은 구간별 차이가 모두 있다.

별도 calibration에서 온도를 학습하는 것은 신경망 확률 보정의 검증된 출발점이다. 다만 해당 방법이 이 데이터에서 더 복잡한 보정보다 우수한지는 직접 비교해야 한다. [Guo et al., On Calibration of Modern Neural Networks (2017)](https://proceedings.mlr.press/v70/guo17a.html).

현재 [공격 평가](v3_report.py)는 보정 전 예측 평균으로 `implicit_log_prior`를 만들고, 온도 보정 후 확률에서 이를 뺀다. 다음 세 가지를 **분리된 profiling calibration**에서 비교한다.

- 라벨 빈도로 추정한 empirical HW prior.
- 보정 전 예측 평균 prior: 기존 구현 대조군.
- 보정 후 예측 평균 prior.

온도·prior 유무와 조합은 개발 평가에서 비교하고 최종 테스트 전에 고정한다. ECE가 낮아도 키 랭킹이 개선된다고 자동 결론 내리지 않는다. 보정 후 NLL/PI와 약한 계수 GE/SR을 함께 평가한다. 희소 클래스 prior는 smoothing 또는 하한을 기록해 0확률을 방지한다.

단일 헤드의 label smoothing 0.05를 `0/0.02/0.05`와 비교할 가치가 있다. 현재 과소확신의 원인이 smoothing이라고 확정할 수는 없으므로 나머지 조건을 고정한 실험으로 확인한다. label smoothing은 calibration에 영향을 줄 수 있다는 연구 결과가 있지만, 이번 CNN의 효과는 별도 측정해야 한다. [Müller et al., When Does Label Smoothing Help? (2019)](https://papers.nips.cc/paper_files/paper/2019/hash/f1748d6b0fd9d439f71450117eba2725-Abstract.html).

주의할 구현 차이도 있다. [compile_multitask](v3_model.py)는 `label_smoothing` 인자를 받아도 실제로는 sparse CE를 생성하고 해당 인자를 적용하지 않는다. 따라서 현 단일·멀티태스크 비교를 “동일 smoothing”이라고 기록하면 안 된다.

## 4. 약한 계수를 더 학습하되 전체 성능을 함께 감시한다

균등 샘플링에서는 경계 계수 8개가 전체 1024개 중 0.78125%다. 현재의 96샘플 문맥에서 드문 경계 파형이 전체 평균 손실에 주는 영향이 작다. 위치별 차이가 확인되면 초기 균등 학습 후 약한 위치를 더 자주 뽑는 두 단계 학습을 비교할 수 있다.

제안은 전체 샘플링의 일정 비율(예: 20%)을 profiling 진단에서 약한 위치에 배정하고, 나머지 80%는 균등 분포를 유지하는 방식이다. 이는 검증할 실험값이며 확정된 최적 비율이 아니다. 희소 HW 클래스만 과도하게 증폭하는 class weight와는 목적이 다르지만, 위치 재가중도 전체 HW 분포를 바꿀 수 있어 보정과 기준선 재측정이 필요하다.

현재 `coeff_weights`는 k축만 재가중하고 poly마다 다른 `(j,k)` 가중치를 직접 받지 않는다. `(poly0,k0)`처럼 특정 위치만 약하면 `(4,256)` 가중치 또는 명시적인 약한 쌍 목록을 처리하도록 샘플러를 확장해야 한다. 학습 데이터에서 측정한 품질로 가중치를 만들고, 새 calibration에서 확률을 보정한다.

채택 기준은 전체 계수 평균만 올리는 것이 아니라 **PI p5·최솟값 및 경계 Top-1을 개선하면서 내부 계수 NLL의 손실을 제한하는 것**이다. 허용할 손실·개선폭은 반복 seed의 변동을 보고 정한다.

## 5. 학습량을 비교할 때 epoch보다 업데이트 수를 사용한다

현재 epoch은 60,000 step이며, 샘플러가 무작위로 반복 추출하므로 epoch 한 번이 고유 `(trace,poly,coeff)` 조합을 한 번씩 방문하는 전수 순회는 아니다. 44 epoch은 2,640,000 optimizer update, 1,351,680,000회 윈도우 추출이다.

지표 확인 간격을 더 짧게 하는 방법은 epoch당 step을 줄이는 것이다. 예를 들어 동일한 총 업데이트 예산에서 10,000 step마다 고정 validation을 수행하면 학습률과 조기 종료를 더 촘촘히 결정할 수 있다. **이때 patience 8을 그대로 두면 조기 종료 대기 예산이 480,000 → 80,000 update로 바뀐다.** patience, LR scheduler, 최대 epoch을 업데이트 수 기준으로 함께 환산해야 공정하다.

현재 learning rate는 epoch 31에 `1e-6` 하한에 도달했고 epoch 36 이후에는 개선이 없었다. 동일 모델을 무작정 더 오래 돌리는 것보다 고정 validation, 윈도우·표현 변경, calibration을 먼저 점검할 근거가 있다. 초기 LR `1e-3`과 `3e-4`는 동일 업데이트 예산으로 비교할 수 있지만, 이번 이력만으로 낮은 LR이 더 좋다고 단정하지 않는다.

검증 Top-1이 train Top-1보다 높은 현상은 dropout, 증강, train/inference 모드와 표본 차이의 영향을 받는다. 과소적합 여부는 **증강 없이 inference 모드로 측정한 학습 표본 성능**과 고정 validation을 비교해 판단한다.

성능 좋은 하드웨어의 이점은 전체 데이터와 더 많은 계수 진단에 사용한다. 배치 크기 증가는 최적화 동역학과 BatchNorm 통계도 바꾸므로, 처리량과 성능을 같이 측정한 후 선택한다. Python 샘플러 벡터화·prefetch 최적화는 입력/라벨 일치 검사를 통과한 뒤 도입한다.

## 6. 멀티태스크와 앙상블은 기본 진단 이후에 비교한다

현재 실행된 모델은 33클래스 HW 단일 헤드다. [멀티태스크 구현](v3_model.py)은 sign·byte0·byte1·byte2와 HW를 공유 트렁크에서 학습할 수 있지만 이번에 CNN 실측하지 않았다. [head_baseline.json](head_baseline.json)은 이전 선형 프로브의 기준값이므로 이번 단일 CNN 결과로 덮어쓸 근거가 없다.

멀티태스크는 별도 고정 calibration에서 헤드별 보정·PI·한계 기여를 측정한 뒤 쓸 헤드를 선택한다. sign과 상위 바이트처럼 중복 정보가 있으므로 헤드별 PI를 단순 합산하거나 확률을 독립이라고 가정해 곱한 결과를 신뢰하지 않는다. 실제 후보 랭킹의 개선과 약한 위치의 손익을 확인한다.

앙상블은 다른 seed 3개 또는 문맥 길이가 다른 모델을 비교하는 후순위 실험이다. [v3_ensemble.py](v3_ensemble.py)의 결합 가중치도 calibration에서만 선택한다. 경계 계수에서 오류가 동일한 모델을 추가하면 비용만 늘 수 있으므로 오류 상관, PI p5, 추론 시간을 함께 보고한다.

## 7. “전체 키 복구”를 주장하려면 평가를 확장해야 한다

현재 65,254개 후보 표본, 대표 계수 한 개의 SR 100%는 유용한 개발 기준선이다. 그러나 `GE × q/n_candidates`가 0이 되는 것은 전체 공간의 미표본 후보까지 제거됐다는 증거가 아니다. PI 기반 최악 계수 필요 트레이스 약 12.32개도 복구 보증이 아니다.

다음 검증은 후보 seed를 바꿔 반복하고, 약한 계수·중간 계수·강한 계수의 GE/SR을 동일 프로토콜로 비교하는 것부터 시작한다. 후보 표본 확대는 수치의 민감도를 확인하는 단계이고, 최종 확인은 q공간 후보를 블록으로 완전 열거해 점수·동점·정답 순위를 계산하는 방식이다. 전체 점수 행렬을 메모리에 적재할 필요 없이 후보 블록별 누적 계산이 가능하다.

1024계수 전체 복구율을 측정할 때는 각 계수에 공통 공격 트레이스 순서를 사용하고, 같은 N에서 **모든 계수가 동시에 성공한 실험 비율**을 계산해야 한다. 개별 계수 성공률 평균과 전체 키 SR은 다르다. 오라클과 CNN은 반복 수·트레이스 선택·길이를 맞춰 비교한다.

또한 중심 잔여류로 바꾼 키의 MR 출력이 원래 라벨과 0.061416% 다름을 확인했다. 후보 대표원과 구현의 overflow 규칙을 정리하고, 복구 목표가 NTT 잔여류인지 저장된 원래 정수 대표원인지 명시해야 한다. 정확한 signed HW 가설 모델을 고치지 않고 단순 모듈러 동등성을 가정하면 소수 트레이스에서 점수 누적이 왜곡될 수 있다.

## 실험 순서와 확인 기준

아래 순서는 지금 관측된 병목을 먼저 확인하도록 구성했다. 모든 실험은 동일 split·고정 평가 입력·동일 업데이트 예산을 사용하고, 유망한 변경만 여러 학습 seed로 재확인한다.

| 순서 | 실험 | 근거 | 주요 확인 지표 |
|---|---|---|---|
| A | 1024계수 진단, train-only 시간 매핑, split·manifest 정비 | 경계 차이 17.052%p, 선택/calibration 재사용 | 위치별 NLL·PI p5, 전처리 provenance |
| B | 경계/내부 offset 비교 및 문맥 브랜치 | 고정 96샘플이 이웃 연산 포함 | 경계 Top-1·PI, 내부 성능 |
| C | 약한 위치 oversampling | 경계 비중 0.78125% | 전체·경계 성능, 보정 후 PI |
| D | smoothing·온도·prior 조합 비교 | 보정 후 NLL/ECE 개선, 잔여 과신 | held-out NLL/ECE, GE/SR |
| E | 검증 간격·LR 조정 | 매우 긴 epoch, 랜덤 validation | 업데이트당 성능, 재현 변동 |
| F | 멀티태스크·앙상블 | 단일 HW 이후 표현 확장 가능성 | 한계 PI, 약한 계수 SR, 추론 비용 |
| G | 후보 확대·q 전량·공통 트레이스 전체 키 평가 | 현재 후보 표본·1계수 평가 | 1024계수 동시 SR, 대표원 불일치 |

각 실행은 데이터/정규화/time-map/model 해시, 전처리 config·통계, split 트레이스 ID, Python·패키지 버전, TF와 NumPy seed, optimizer update 수, validation 목록, 보정 설정과 후보·트레이스 seed를 보존한다. 현재 학습 실행기는 NumPy seed만 설정하고 TF 초기화 seed와 optimizer/callback 상태까지 복원하는 완전 resume를 제공하지 않는다. seed 반복과 resume를 사용할 때 먼저 보완할 항목이다.

현재까지 확실한 개선 대상은 경계 구간과 평가 재현성이다. 실제 정확도·복구 성능의 개선폭은 위 실험으로 확인해야 하며, 이 글의 제안값을 성능 보장으로 해석하지 않는다.

## 8. 문헌 비교를 반영한 연구 단위의 보완

위 A~G는 구현 실험의 순서다. 연구 결과로 비교하려면 그 전에 동일 데이터·동일 split의 CPA/템플릿/MLP/CNN 기준선을 정의하고, 이후 단계마다 같은 후보 식·트레이스 순서로 GE/SR을 측정해야 한다. 모델 정확도만 비교하는 것보다 약한 계수의 후보 축소와 종단간 복구 성능을 함께 비교하는 것이 중요하다.

선행 연구에는 한 트레이스를 다수 계수 윈도우로 확장한 사례와 위치 유형별 모델이 있다. 따라서 “1024윈도우 활용” 자체를 신규성으로 주장하기보다, 공유 모델 대비 위치 조건부·확률 보정이 같은 예산에서 어떤 추가 이득을 주는지 확인한다. 부분 NTT 계수 복구 후 구조적 후처리는 유망한 대조 전략이지만, 현재 `s`의 실제 작은 secret 구조와 NTT/Montgomery 규약을 먼저 확인해야 한다.

기존 데이터로 할 수 있는 작업과 공개키·서명·새 측정이 필요한 작업, 각 논문의 추가 정보 조건은 [선행 연구 보고서](related_work_analysis.md)에 구분해 두었다. 아직 후처리 구현이나 개선 학습을 실행한 상태는 아니다.
